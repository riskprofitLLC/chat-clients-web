# Web-клиент мессенджера

E2E-клиент в браузере: история сообщений живёт **только на устройстве** (IndexedDB,
записи зашифрованы AES-GCM), сервер видит только opaque-блобы. Wire-формат
байт-в-байт совпадает с Android и крипто-модулем — проверено кросс-языковыми
фикстурами (Java ↔ TypeScript) и векторными тестами.

## Стэк

- TypeScript (strict) + vanilla DOM, **без фреймворков и без прод-зависимостей**
- Крипта — WebCrypto (ECDH P-256, HKDF-SHA256, AES-GCM)
- Сборка — Vite, тесты — Vitest; dev-зависимости: `typescript`, `vite`, `vitest`
- Звонки — `RTCPeerConnection` + `getUserMedia`, сигналинг `TYPE_CALL` в sealed-блобах
- PWA: свой манифест и сервис-воркер (офлайн-шелл, уведомления, Web Push)

## Команды

```bash
cd clients/web
npm ci
npm test                 # 76 тестов: крипта (векторы + кросс-язык), протокол, домен, регрессии
npm run typecheck
npm run build            # → dist/ (статика + sw.js с реальным прекэшем)
npm run dev              # :5173, /v1 проксируется на релей (CHAT_RELAY_PORT)
node scripts/make-icons.mjs   # перегенерировать иконки PWA (включая maskable)
```

Локальная связка с релеем:

```bash
cd go && CHAT_RELAY_ADDR=:18080 CHAT_DEV_MODE=1 go run . &
cd clients/web && CHAT_RELAY_PORT=18080 npm run dev
# открыть http://127.0.0.1:5173/ — в dev-режиме релей возвращает email-код
# прямо в ответе, а клиент по умолчанию бьёт в свой origin (vite проксирует /v1)
```

## Деплой

```bash
cd clients/web && npm ci && npm run build
# статика копируется на сервер в deploy/site/web (рядом с сайтом-визиткой)
# Caddy отдаёт её как https://<домен>/web/ (см. deploy/Caddyfile, блок @web)
```

Прод-адрес по умолчанию: `https://ednar.duckdns.org`, клиент открыт как
`/web/`. В проде адрес меняется в «Настройки» (отдельного скрытого параметра
`?server=` нет: только в dev-сборке).

## Что умеет

- Регистрация по email-коду, вход, привязка нового устройства (единый код
  `nonce.ключ`), список устройств, перенос истории на новое устройство
- Текст, ответы/цитаты, реакции (любой эмодзи), правка, «удалить у всех»,
  закрепы, черновики (синк между своими устройствами), группы (создание,
  участники, имя, описание), опросы с голосованием, геопозиции, карточки
  контактов, фото/файлы/голосовые (шифрованный блоб + превью)
- TOFU: смена ключей собеседника блокирует отправку до подтверждения;
  6-значный код безопасности (SafetyCode) на экране информации о чате
- Статусы: «в сети», «печатает», галочки «отправлено → доставлено → прочитано»,
  приватность presence
- **Звонки 1:1** (аудио, WebRTC): исходящие/входящие, рингтон с каденцией,
  mute, Wake Lock, таймаут неотвеченного вызова, запись в журнал звонков.
  Сигналинг — `TYPE_CALL` в sealed-блобе, сервер не видит SDP
- Outbox: при обрыве сети сообщения не теряются, доигрываются с backoff;
  постоянные ошибки (4xx) показываются с «Повторить/Удалить»
- Уведомления (Notification API + Web Push), офлайн-шелл, обновление по кнопке
- Темы (auto/светлая/тёмная) и шесть акцентов, всё в UI

## Архитектура UI

```
src/ui/
  dom.ts          минимальные DOM-хелперы + keyed-обновление списков
  icons.ts        свои inline-SVG иконки (24×24, stroke 1.75) — без эмодзи
  theme.ts        темы и акценты (data-theme / data-accent)
  host.ts         контракт «оболочка ↔ экраны» (состояние, навигация, данные)
  state/store.ts  один стор + планировщик перерисовки на requestAnimationFrame
  screens/        login, chats, dialog, settings
  components/     modal (единый диалог вместо prompt/confirm), snackbar,
                  message-menu, call-overlay, avatar
  styles/         tokens.css → base.css → components.css → screens.css
src/i18n/ru.ts    все строки интерфейса
```

- Ввод, поиск и скролл не сбрасываются при входящих событиях: композер и
  строки списка не пересоздаются, обновляется только изменившееся
- Реакции и голоса считаются одним проходом по журналу на чат
  (`Messenger.chatSnapshot`) и кэшируются в состоянии
- Таймер звонка обновляется точечно, экран не перерисовывается
- Маршрутизация — по hash (`#/chat/<id>`, `#/settings`): работает кнопка
  «назад» браузера и жест на мобильных

## Потолки web-платформы (осознанные)

1. **TURN обязателен для звонков.** Android-фокус с UDP-мостом
   (`CallPipeBridge`) в браузере невозможен. Без TURN звонки не проходят через
   симметричный NAT и мобильные сети (CGNAT). Настраивается в «Настройки →
   Звонки» (STUN по умолчанию: `stun:stun.l.google.com:19302`).
2. **Входящий звонок при закрытой вкладке — уведомление, не вызов.** В Service
   Worker нельзя поднять WebRTC. Пуш разбудит и покажет уведомление; ответ —
   после открытия вкладки. Offer лежит в очереди (TTL 30 дней).
3. **Safari удаляет IndexedDB через 7 дней** без взаимодействия с сайтом, если
   приложение не добавлено на домашний экран. Поэтому установка PWA —
   обязательное условие: без неё локальная история (весь смысл продукта)
   исчезает. Клиент просит установить приложение и предупреждает.
4. **iOS: нет CallKit** — системного экрана вызова и ответа с локскрина. Web
   Push на iOS работает только для приложений на домашнем экране (iOS 16.4+).
5. **Крипта в браузере слабее, чем в Android:** нет аппаратного хранилища
   (Keystore/Keychain), ключ данных лежит в IndexedDB. Это защищает от чтения
   файлов профиля, но не от XSS на нашем домене. Клиент честно пишет об этом на
   экране входа и в настройках.
6. **Аватары отключены** до согласования формата с Android (см. ниже).

## Безопасность wire-формата

- Конверты v3 (`0xC5 0xA5 '3'`), sealed box `[SPKI 91][IV 12][ct||tag]`,
  HKDF по RFC 5869 — байт-в-байт с `crypto/`; см. `test/crypto.test.ts`
  (векторы RFC 5869/4231/5903, McGrew-Viega, кросс-языковая фикстура JCA).
- Журнал: запись `[len from 2Б][from][ts 8Б][content]`, на диске —
  `IV||AES-GCM(запись, AAD=chatId)`; формат тот же, что в Kotlin
  (`JournalMessageStore`), история переносится между Android и web.
- Серверная авторизация WebSocket: токен в подпротоколе `chat.bearer.<token>`
  (браузер не ставит заголовки на WS); см. `go/ws.go` (`wsAuth`).
- CSP (`index.html` + заголовок Caddy): `default-src 'self'`,
  `script-src 'self'` (без inline и eval), `object-src 'none'`,
  `base-uri 'none'`, `frame-ancestors 'none'`, `form-action 'none'`.

## Требует согласования (не сделано молча)

1. **Аватары.** Поле `ava` в дескрипторе медиа не зафиксировано в общем
   формате: парсер Android его не ставит, из-за чего фото рассылалось как
   обычное медиа-сообщение во все чаты. Кнопка скрыта, `setAvatar` отклоняет
   вызов до согласования wire-формата.
2. **`secret` в query-строке** выдачи токена привязки (`GET /v1/link/{nonce}/token?secret=`) — одноразовый секрет из QR.
   Секрет попадает в логи доступа; хотелось бы заголовок или POST.
3. **Web Push:** серверная половина (VAPID-ключ релея и адаптер к пуш-шлюзу)
   не реализована. Клиентская подписка готова, но без ключа релея тумблер
   остаётся локальными уведомлениями.
4. **Отзыв устройства при logout** реализован через `POST /v1/devices/revoke`
   (свой токен). Если нужен отзыв всех сессий — отдельный эндпоинт.
