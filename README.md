# Web-клиент мессенджера

E2E-клиент в браузере: история сообщений живёт **только на устройстве** (IndexedDB,
записи зашифрованы AES-GCM), сервер видит только opaque-блобы. Wire-формат
байт-в-байт совпадает с Android и крипто-модулем — проверено кросс-языковыми
фикстурами (Java ↔ TypeScript) и векторными тестами.

## Стэк

- TypeScript (strict) + vanilla DOM, **без фреймворков и без прод-зависимостей**
- Крипта — WebCrypto (ECDH P-256, HKDF-SHA256, AES-GCM)
- Сборка — Vite, тесты — Vitest; dev-зависимости: `typescript`, `vite`, `vitest`
- Звонки — `RTCPeerConnection` + `getUserMedia`, сигналинг `TYPE_CALL` в sealed-блобах
- PWA: свой манифест и сервис-воркер (офлайн-шелл, уведомления, Web Push)

## Команды

```bash
cd clients/web
npm ci
npm test                 # 61 тест: крипта (векторы + кросс-язык), протокол, домен
npm run build            # → dist/ (статика)
npm run dev              # :5173, /v1 проксируется на релей (CHAT_RELAY_PORT)
node scripts/make-icons.mjs   # перегенерировать иконки PWA
```

Локальная связка с релеем:

```bash
cd go && CHAT_RELAY_ADDR=:18099 CHAT_DEV_MODE=1 go run . &
cd clients/web && CHAT_RELAY_PORT=18099 npm run dev
# открыть http://127.0.0.1:5173/ — на экране входа можно сменить адрес сервера;
# в dev-режиме релей возвращает email-код прямо в ответе
```

## Деплой

```bash
cd clients/web && npm ci && npm run build
# статика копируется на сервер в deploy/site/web (рядом с сайтом-визиткой)
# Caddy отдаёт её как https://<домен>/web/ (см. deploy/Caddyfile, блок @web)
```

Прод-адрес по умолчанию: `https://riskprofit.duckdns.org`, клиент открыт как
`/web/`. Адрес можно сменить на экране входа — он хранится в настройках.

## Что умеет

- Регистрация по email-коду, вход, привязка нового устройства (код + опрос),
  список устройств, перенос истории на новое устройство
- Текст, ответы/цитаты, реакции (любой эмодзи), правка, «удалить у всех»,
  закрепы, черновики (синк между своими устройствами), группы (создание,
  участники, имя, описание), опросы с голосованием, геопозиции, карточки
  контактов, фото/файлы/голосовые (шифрованный блоб + превью)
- TOFU: смена ключей собеседника блокирует отправку до подтверждения;
  6-значный код безопасности (SafetyCode) на экране информации о чате
- Статусы: «в сети», «печатает», доставлено/прочитано, приватность presence
- **Звонки 1:1** (аудио, WebRTC): исходящие/входящие, рингтон, mute, Wake Lock,
  запись в журнал звонков. Сигналинг — `TYPE_CALL` в sealed-блобе, сервер не
  видит SDP.
- Outbox: при обрыве сети сообщения не теряются, доигрываются автоматически
- Уведомления (Notification API + Web Push), офлайн-шелл

## Потолки web-платформы (осознанные)

1. **TURN обязателен для звонков.** Android-фокус с UDP-мостом
   (`CallPipeBridge`) в браузере невозможен. Без TURN звонки не проходят через
   симметричный NAT и мобильные сети (CGNAT). Настраивается в «Настройки →
   Звонки» (STUN по умолчанию: `stun:stun.l.google.com:19302`).
2. **Входящий звонок при закрытой вкладке — уведомление, не вызов.** В Service
   Worker нельзя поднять WebRTC. Пуш разбудит и покажет уведомление; ответ —
   после открытия вкладки. Offer лежит в очереди (TTL 30 дней).
3. **Safari удаляет IndexedDB через 7 дней** без взаимодействия с сайтом, если
   приложение не добавлено на домашний экран. Поэтому установка PWA —
   обязательное условие: без неё локальная история (весь смысл продукта)
   исчезает. Клиент показывает баннер, а на Safari — предупреждение всегда.
4. **iOS: нет CallKit** — системного экрана вызова и ответа с локскрина. Web
   Push на iOS работает только для приложений на домашнем экране (iOS 16.4+).
5. **Крипта в браузере слабее, чем в Android:** нет аппаратного хранилища
   (Keystore/Keychain), ключ данных лежит в IndexedDB. Это защищает от чтения
   файлов профиля, но не от XSS на нашем домене. Клиент честно пишет об этом на
   экране входа и в настройках.

## Безопасность wire-формата

- Конверты v3 (`0xC5 0xA5 '3'`), sealed box `[SPKI 91][IV 12][ct||tag]`,
  HKDF по RFC 5869 — байт-в-байт с `crypto/`; см. `test/crypto.test.ts`
  (векторы RFC 5869/4231/5903, McGrew-Viega, кросс-языковая фикстура JCA).
- Журнал: запись `[len from 2Б][from][ts 8Б][content]`, на диске —
  `IV||AES-GCM(запись, AAD=chatId)`; формат тот же, что в Kotlin
  (`JournalMessageStore`), история переносится между Android и web.
- Серверная авторизация WebSocket: токен в подпротоколе `chat.bearer.<token>`
  (браузер не ставит заголовки на WS); см. `go/ws.go` (`wsAuth`).
